Репозиторий переведён на Cargo workspace. Интерфейс и прикладные сервисы написаны на Rust; Python, Flet, Flutter и PyO3 не участвуют в запуске и сборке. Структура `App/app`, `App/settings`, `App/services`, `App/assets` и `Services` сохранена.

**Перенос всех возможностей Flet ещё не завершён.** Встроенные локальные модели, инструменты агента и автоматически создаваемый профиль уже работают. Live, облачные сервисы и отдельные защищённые чаты пока не перенесены. Подробный статус — [MIGRATION.md](MIGRATION.md). Исходники прежней реализации доступны в истории Git.

## Сейчас доступны

- История чатов, поиск названий и сообщений, закладки, переименование, редактирование и удаление сообщений, сохранение черновиков, экспорт Markdown.
- Ответы совместимого Chat Completions API: потоковый текст, отмена запроса, сетевые таймауты. Настраиваются Google AI Studio, OpenRouter или собственный URL. Локальные llama-server и Ollama подключаются тем же способом, их нужно запустить отдельно.
- Встроенная Gemma4-e2b/e4b: скачивание, пауза/продолжение, SHA-256, импорт оригинального `.litertlm` одной кнопкой проводника с автоматическим определением по SHA-256, выбор модели, автоматический GPU/CPU и выгрузка памяти. Используется [официальный LiteRT-LM C API 1.0.0](https://github.com/google-ai-edge/LiteRT-LM/releases/tag/v0.19.1), без Python и внешнего сервера. Настоящая Gemma4-e2b проверена на Linux CPU; e4b и GPU отдельно не испытывались.
- Агент для локальных моделей и API: чтение/поиск/изменение файлов выбранного проекта, команды, Canvas, поиск чатов и память. По умолчанию инструменты выключены; режим выбирается кнопкой рядом с моделью. Ручной режим показывает запись/команду перед выполнением. Автоматический режим включается явно. Есть пауза, остановка, журнал результатов и защита от повторяющихся действий.
- Профиль устройства создаётся автоматически при первом запуске, без регистрации и пароля. Имя и аватар редактируются по нажатию; UUID и история сохраняются между запусками. Прежние файлы локальных аккаунтов не удаляются.
- Вход через Google и почту, регистрация с подтверждением email используют прежний серверный `/api/v1`. Проверка настоящей авторизации отложена до включения сервера.
- Вложения: текст/код, PDF, DOCX, JPEG/PNG/WebP/BMP/GIF. Изображения уменьшаются перед отправкой. Неудачное чтение отдельного файла становится пометкой для модели.
- Проекты с инструкциями, привязкой чатов и папкой: список файлов, поиск по коду, Git status и diff --stat, редактор с проверкой внешних изменений.
- Canvas: Markdown, код и изолированный HTML-предпросмотр, сохранение документов. Рисунки прежней версии сохраняются, редактора рисования пока нет.
- Создание и редактирование шаблонов запросов, имя и аватар по нажатию, личные инструкции, семь цветовых тем с тематическими списками, адаптивная компоновка для узкого экрана. При закрытии изменённой формы запрашивается подтверждение.

Внешний API получает историю выбранного чата и прикреплённые к сообщениям материалы. Он не получает всю базу. Локальные материалы и экспортированные Markdown-файлы лежат вне SQLCipher в каталоге данных приложения.

## Автоматическое устройство

По умолчанию включено **Автоматически · GPU / CPU**. Приложение проверяет свободную VRAM через счётчики DRM/NVIDIA, а на Android — доступную общую RAM. Оценка оставляет запас: двойной размер весов плюс 2 ГиБ. При неизвестном объёме или недостатке памяти выбирается CPU. Если GPU не запустился до первого выданного токена, выполняется переход на CPU. Уже загруженная модель повторно использует своё устройство; её занятая VRAM не считается чужим расходом.

Это выбор вычислительного backend, а не перенос SQLCipher на GPU. История остаётся на диске, сообщения — в оперативной памяти; размещением тензоров и KV-кеша управляет LiteRT. Ручной выбор сохранён в персонализации. Реальный GPU и физический Android ещё не испытаны.

## Интерфейс

Дополнительные окна имеют общий размер и прокручиваемое содержимое. Уведомления и прогресс находятся над вводом в чате; вне чата — в правом верхнем углу приложения. Каждый раздел окна сохраняет собственную прокрутку. Известный размер сопровождается процентом и объёмом; неизвестный отображается отдельным индикатором. Анимации меняют только прозрачность и transform; `prefers-reduced-motion` отключает движение.

Компоновка возвращена к Flet-версии: узкая панель и выдвижное меню, компактный заголовок и ввод, исходные иконки/палитры, сообщения и настройки поверх чата. [Сверка с оригиналом и снимки](previews/FLET_PARITY.md).

## Запуск на Linux

Нужны Rust stable, системные библиотеки WebKitGTK/GTK3 и Dioxus CLI той же версии, что в Cargo.lock.

```bash
# Arch Linux
sudo pacman -S --needed base-devel pkgconf perl gtk3 webkit2gtk-4.1 xdotool curl unzip zip

# Debian / Ubuntu с WebKitGTK 4.1
sudo apt-get install build-essential pkg-config perl libgtk-3-dev libwebkit2gtk-4.1-dev libxdo-dev curl unzip zip

cargo install dioxus-cli --version 0.7.10 --locked
./scripts/prepare_runtime.sh
dx serve --desktop -p xopilot
```

Для сборки приложения вместе со шрифтом и иконкой:

```bash
./scripts/build_linux.sh
# Результат: target/dx/xopilot/release/linux/app/
```

В приложении откройте **Выбор модели**, скачайте Gemma и нажмите **Выбрать**. Первый ответ загружает веса в память. Следующие сообщения дополняют готовый контекст LiteRT; изменение прежних сообщений/инструкций пересоздаёт его. Смена чата сбрасывает контекст; веса остаются загруженными. У агента сохраняется также внутренняя история вызовов инструментов. При приближении к лимиту KV-кеш пересобирается из краткой истории без повторной загрузки весов. Контекст сейчас ограничен 4096 токенами, автоматическое сжатие длинных разговоров ещё не перенесено. Для API используйте **Выбор модели → Подключить API**. Например, уже запущенный `llama-server` обычно доступен по `http://127.0.0.1:8080/v1`; идентификатор модели задаётся в форме.

`prepare_runtime.sh` нужен разработчику при сборке: он скачивает закреплённый SDK и проверяет архив. Linux-библиотека встраивается в бинарник; Android-библиотека упаковывается в APK. Пользователю не нужны Rust, Cargo, Python или отдельная установка LiteRT. Сборка без подготовленного SDK сохраняет работу API, но не запускает встроенную модель.

## Android

Используется тот же Rust-интерфейс с Dioxus Mobile и системным WebView, без Python/Flutter. Собран debug APK для arm64: прежний application ID `by.xopilot.app`, минимум API 26, target/compile 35. Проверено наличие `liblitert-lm.so` в APK. Запуск, Keystore и модель на физическом телефоне ещё не проверены.

```bash
rustup target add aarch64-linux-android
export JAVA_HOME=/path/to/jdk-21
export ANDROID_HOME=/path/to/Android/Sdk
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/27.2.12479018"

# После установки SDK platform 35, build-tools 34.0.0/35.0.0 и NDK:
./scripts/build_android.sh
# Для запуска на подключённом устройстве:
dx serve --android -p xopilot --no-default-features --features mobile --target aarch64-linux-android
```

Выбор произвольной папки проекта через Android SAF ещё не реализован: путь должен быть доступен приложению. Для вложений добавлен отдельный системный chooser WebView: данные передаются в Rust блоками по 64 КиБ. Работу с Android content URI необходимо проверить на устройстве. Для обновления старой установки нужна **прежняя подпись APK**: debug-сборка с другим ключом её не заменяет и не получает доступ к прежнему Keystore. Шаблон Dioxus также задаёт versionCode=1; перед выпуском обновления нужен больший код сборки. Автоматической публикации новых релизов пока нет.

## Данные и проверки

Linux использует прежний `$XDG_DATA_HOME/Xopilot` (по умолчанию `~/.local/share/Xopilot`), Windows — `%APPDATA%/Xopilot`. Файл базы — `xopilot.db`. Схема SQLCipher, имена ключей настроек и разрешение ключа шифрования сохранены. При потере ключа приложение показывает ошибку, не создавая новую историю поверх старой. На Android JNI использует прежние `xopilot_keys` / `xopilot.database.v1`; это пока проверено компиляцией JNI-кода, а не обновлением APK на телефоне.

Для отдельного тестового профиля можно задать `XOPILOT_DATA_DIR=/tmp/test/Xopilot`. `XOPILOT_MODELS_DIR` меняет каталог весов; большие файлы лучше держать на диске, поскольку `/tmp` может быть tmpfs. Веса общие для устройства. Автоматический профиль использует основной `xopilot.db`. Старые файлы `accounts/<id>` сохранены, но локальная регистрация и переключение этих профилей удалены. История и API-ключи зашифрованы. Материалы и экспорты, как и раньше, являются обычными файлами вне SQLCipher. Облачная синхронизация не запускается.

Агент исполняет команды с правами пользователя устройства в выбранной папке проекта; это не изолированная ОС-песочница. Команда ограничена 60 секундами и объёмом вывода; остановка завершает также её дочерние процессы на Linux/Android. Долгоживущие серверные процессы и управление другими устройствами пока не перенесены.

```bash
# Сервисные тесты и рендер Dioxus не требуют графического окружения:
cargo test --workspace --no-default-features --locked
cargo clippy --workspace --all-targets --no-default-features --locked -- -D warnings
cargo fmt --all --check
# С установленными системными зависимостями:
cargo check --workspace --locked
```

Пользовательские сценарии в настоящем Linux WebKit, на отдельной временной базе:

```bash
dx build --desktop -p xopilot --example interface_interaction
node scripts/check-ui.cjs
```

Стенд проверяет клики, ввод, сохранение, потоковый ответ тестового API, отмену, закладки, конфликты редактора, агента с подтверждениями, карточки его действий и автоматический профиль. На Niri дополнительно меняет ширину окна с 1000 на 390 px. Мост существует только в тестовом примере. [Результаты интерфейсной проверки](tests/UI_REVIEW.md).

Для проверки настоящей локальной генерации в том же UI задайте `XOPILOT_TEST_MODEL=/путь/gemma-4-E2B-it.litertlm` перед `node scripts/check-ui.cjs`. Стенд импортирует и проверяет веса в отдельном каталоге `target/ui-models`, не в личный профиль. Отдельные примеры `local_model_smoke`, `local_context_smoke`, `local_agent_smoke` и `local_canvas_smoke` проверяют ответ, повторное использование контекста и инструменты без WebView.

Для быстрой проверки используйте одну команду:

```bash
./scripts/test.sh             # Rust-тесты сервисов и рендера
./scripts/test.sh full        # Также форматирование и Clippy
./scripts/test.sh ui          # Настоящее окно, клики и отдельная база
./scripts/test.sh model /путь/gemma-4-E2B-it.litertlm
```

`ui` требует Node.js и графического Linux-сеанса; на Niri проверяются также узкое окно и снимки. В установленное приложение тестовый мост не входит. Google и настоящий сервер аккаунтов эти команды не вызывают. Подробности — [tests/TESTING.md](tests/TESTING.md).

## Устройство проекта

```text
Cargo.toml             workspace и общие профили сборки
Dioxus.toml            упаковка и платформы
App/
  main.rs              точка входа
  lib.rs               объявления слоёв
  app/                 окно, меню, чат, Canvas, проекты и тема
  settings/            настройки и персонализация
  services/            прикладная логика и фоновые задачи
  assets/              графика, шрифты и прежние ресурсы
  tests/               интеграционные тесты Rust и рендер интерфейса
Services/
  src/db/              SQLCipher и прежние миграции
  src/security/        ключи шифрования
  tests/               проверки шифрованной истории
scripts/               команды разработки и сборки
```
