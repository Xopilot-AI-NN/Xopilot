# Xopilot-AI+ NN+

Xopilot — локальный помощник с чатом, рабочими пространствами, документами и голосовым разговором Live. Интерфейс — Python/Flet, история — Rust/SQLCipher, ИИ — LiteRT-LM, озвучивание — Piper и локальный RVC для Miku.

Версия приложения: 2.0.0. Статус на 3 октября 2026: рабочая локальная сборка Linux; полный релиз для Linux и Windows ещё не подтверждён. Облако, аккаунты и синхронизация запланированы следующим этапом. Подробные результаты: [проверки через интерфейс](docs/USER_CHECKS.md) и [готовность локальной версии](docs/LOCAL_RELEASE_STATUS.md).

## Возможности текущей версии

- Чаты: создание, поиск, переименование, перенос между пространствами, редактирование и удаление сообщений, очистка текущего чата.
- Раскрытое меню показывает чаты, поиск, текущий выбор и число сообщений.
- Защищённые анонимные чаты с отдельным паролем и временная версия: локальный ИИ, изоляция от профиля/проектов, собственные вложения и Canvas. [Использование и границы защиты](docs/PRIVATE_CHATS.md).
- Рабочие пространства: собственные инструкции для ИИ и общие документы для всех чатов пространства.
- Вложения: локальные копии, анализ текста, PDF, DOCX, изображений и кадров видео поддерживаемой моделью.
- Live: локальное распознавание, ответы и озвучивание; выбор устройств, отключение микрофона и озвучивания, текстовые вопросы и файлы, камера или экран, прерывание ответа и завершение разговора. Ответ виден в окне звонка и сохраняется в чате. Для визуального вопроса передаётся текущий кадр, а не непрерывный видеопоток.
- Диктовка в черновик, сохранение черновиков отдельных чатов, остановка и повтор ответа без дублирования вопроса.
- Светлая и тёмная темы, локальный профиль, выбор моделей и голосов COVE/Miku/Maple, установка моделей, проверка опубликованных обновлений.
- Miku использует отдельную обученную модель тембра сообщества, русский и английский; [установка, образцы и проверки](docs/MIKU_VOICE.md).
- Экспорт текста чата в Markdown с предпросмотром и копированием. Исходные файлы вложений в экспорт текста не включаются.

Интерфейс русский; настройка языка меняет предпочтительный язык ответов ИИ. История, настройки и метаданные зашифрованы SQLCipher. Содержимое копий материалов хранится отдельными локальными файлами без этого шифрования.

## Запуск из проекта на Linux

Используйте Python 3.14. Нативное расширение должно соответствовать версии Python и платформе:

    ./python/linux/bin/python scripts/build_native.py --offline
    ./python/linux/bin/flet run -r --ignore-dirs "data,__pycache__,.pytest_cache" App/App.py

Флаг --offline подходит, если зависимости Cargo уже закэшированы; иначе уберите его. На Linux для звука нужен PortAudio; для доступа к устройствам требуются обычные разрешения ОС. Одна запись диктовки ограничена 30 секундами.

Тот же интерфейс можно открыть локально в браузере:

    ./python/linux/bin/python scripts/run_web.py

Адрес: http://127.0.0.1:8559. В этом режиме камера, экран, микрофон и модели принадлежат компьютеру, где работает Python-процесс. Сервер слушает только loopback. Первый запуск веб-клиента может требовать загрузки ресурсов Flutter из CDN. Флаг --test-profile запускает отдельный профиль для проверки и не меняет пользовательскую историю.

## Новые возможности локального интерфейса

- Чаты автоматически получают название по первому вопросу; ручное переименование сохраняется. История ищет по названиям и сообщениям.
- Рабочие пространства: иконки проектов, инструкции, библиотека файлов/папок/заметок и связанные чаты.
- Canvas: сохраняемые текст, код и рисунки, экспорт и прикрепление к сообщению.
- Экспорт чата и Canvas умеет сохранять «Локальную копию» с показом пути к файлу; экспортируемый файл находится вне защиты паролем.
- Агентность в строке ввода: низкая, средняя, высокая и Авто. Агент использует инструменты библиотеки и Canvas с журналом действий.
- Семь тем, одинаковые обводки полей/списков и градиентные кнопки меню/чата.
- Выбор модели: Zephyr Micro (в разработке), Gemma4-e2b, Gemma4-e4b и API. API настраивается через URL Chat Completions, идентификатор модели и ключ. При выборе API данные текущего запроса отправляются указанному провайдеру; Live использует локальную модель. Ключ хранится в зашифрованной БД.

## Модели и данные

Установите модель и голоса через «Настройки → Модели». Для Live нужна модель с аудиовходом; для камеры и экрана — с поддержкой изображений. В «Персонализации → Устройство вычислений» доступны Авто, GPU и CPU. Авто предпочитает видеокарту со свободной памятью и небольшой текущей загрузкой; при ошибке загрузки GPU переходит на CPU. Принудительный GPU показывает ошибку вместо скрытого переключения. Звук, обработка изображений и Piper остаются на CPU; даже при GPU часть ОЗУ необходима. GPU LiteRT-LM на Linux/Windows использует совместимый Vulkan-драйвер: [официальная документация](https://developers.google.com/edge/litert-lm/cli/usage). Gemma4-e2b проверена на RTX 3050; E4B ещё не проверена. Тяжёлые веса не входят в пакет приложения. После их установки локальный ИИ и голоса работают без обращения к облачному сервису.

Данные находятся в $XDG_DATA_HOME/Xopilot (по умолчанию ~/.local/share/Xopilot) на Linux и %APPDATA%/Xopilot на Windows. Новые модели находятся там же в models/; прежние App/data/models/ доступны для чтения при запуске из проекта. XOPILOT_MODELS_DIR переопределяет каталог новых моделей.

Временные файлы, рабочая папка и кеш движка также находятся в каталоге пользователя. Приложение не записывает их в App/.flet и не создаёт новый Python-байткод в исходниках, чтобы `flet run -r` не перезапускал его при ответе ИИ. В режиме разработки также можно добавить `.flet` к `--ignore-dirs`.

## Сборка и проверка

    ./python/linux/bin/python -m unittest discover -s tests -q
    cargo test --manifest-path Services/Cargo.toml --offline --lib
    ./python/linux/bin/flet build linux --yes --python-version 3.14

Результат Linux-сборки — каталог build/linux/; запускаемый файл — build/linux/Xopilot. Каталог надо переносить целиком, вместе с библиотеками, Python и ресурсами. Windows собирается на Windows: python scripts/build_native.py, затем flet build windows --yes --python-version 3.14. Windows-сборка и устройства в этой сессии не проверялись.

## История создания
[Август 2023 года] Привет! Я хочу поделиться историей создания Copilot-AI+, или, если использовать полное название, Copilot-AI-NN.
Всё началось с того, что я увидел презентацию от Microsoft о создании помощника Xopilot. Когда я скачал и установил Windows 11, чтобы протестировать Xopilot, он оказался недоделанным. Он мог делать то же, что и обычный ChatGPT, то есть генерировать текст и открывать встроенные программы. Поэтому мне захотелось взяться за Python и создать свою версию.
Я работал над версией 1.1.0 около 3–4 месяца, и, к моему удивлению, она заработала. В этой версии был Python 3.11.4, а для интерфейса я использовал библиотеку PyQt5. Были такие функции, как «Улучшение фото в HDR качество», «Открытие программ» (но только тех, которые были написаны в коде), «Установка тем», «Функция „найди всё“», которая ищет все данные запроса, и ещё несколько функций. Это был важный шаг в развитии Copilot-AI+, который позволил расширить его функциональность.

[Март 2024] После презентации некоторые оценили Copilot-AI+, поэтому я решил создать новую версию. Буквально через неделю ChatGPT перестал работать, поэтому я быстро выпустил обновление 1.2.0, в котором исправил этот баг. Это было важно для сохранения функциональности и стабильности Copilot-AI+.

[Март 2024, вторая половина] Через неделю я выпустил новое обновление 1.3.0, где добавил ядра, то есть я разделил код на две части: 84% кода составляла первая часть, а 16% — вторая. Это ускорило программу. Я также исправил баг, при котором Copilot-AI+ вылетал при отключении интернета. Это обновление значительно улучшило производительность и надёжность Copilot-AI+.

[Апрель 2024] Так вышла новая версия 1.4.0, в которой были внесены значительные изменения. В частности, поменялась версия Python на 3.12.2, а библиотека для интерфейса PyQt5 обновилась до PyQt6. Это обновление было нестабильным: некоторые функции не хотели работать, но если повезёт, они могли функционировать как надо. В частности, ChatGPT стал читать историю, то есть он начал отвечать на предыдущий запрос, но я ограничил чтение истории до 6 сообщений. Следующее изменение заключалось в том, что ChatGPT стал выбирать ответы отдельно и с задержкой, чтобы создать эффект, как будто пишет человек. Это добавило Copilot-AI+ больше «человечности» и сделало его более приятным в использовании.
В целом, создание Xopilot-AI+ было увлекательным и обучающим процессом, который позволил мне улучшить свои навыки в программировании и искусственном интеллекте. Я надеюсь, что Xopilot-AI+ будет полезен и интересен для его пользователей.

[Май 2024] 11 мая было выпущено обновление 1.5.0, в котором произошли глобальные изменения в коде ядра. В частности, была добавлена функция, позволяющая сворачивать и разворачивать Xopilot-AI+ NN+ с помощью комбинации клавиш `Win` + `/`. Кроме того, программа теперь носит название Xopilot-AI+ NN+. В общем, это основные нововведения обновления.

[Февраль 2025] Эх, уже прошёл год от первой версии моей программы, но я готовил на эту дату обновление 1.6.0, но, к сожалению, оно получилось ужасным: во-первых, это выгорание, а во-вторых, то что должно было работать, не работало, поэтому я решил переписать его полностью. Снова сделал иерархическую архитектуру — всё стало на свои места, я смог нормально понимать, что где, вместо того чтобы листать 1 файл с 15+ тыс. строк. Программа стала идеальной, но случилось выгорание, и я заморозил релиз.

[2026] Я собрался с мыслями и, заодно, изучил Rust. Теперь 80% кода напишу на Rust, а интерфейс на PySide6. А также добавлю новые штуки — остаётся просто ждать...
