# Linux: основные окна и отдельный указатель ИИ

В обычном чате или пространстве включите агентность и попросите открыть установленное приложение либо изменить конкретное поле/нажать кнопку. `list_apps` и `launch_app` работают через каталог приложений Gio; произвольный shell здесь не используется.

`computer_start` всегда запрашивает отдельное разрешение на текущую задачу. Системный портал дополнительно разрешает просмотр экрана. `computer_view` возвращает снимок и доступные элементы AT-SPI. `computer_input` вызывает доступное действие (`click`) или заменяет содержимое редактируемого поля (`set_text`). ID берётся из последнего просмотра, после действия ID обновляются. В ручном режиме подтверждение находится в чате и показывает окно, элемент и отправляемый текст; в автоматическом режиме действия выполняются после начального разрешения задачи.

Указатель ИИ — отдельная прозрачная поверхность с отражённым SVG. На Niri она не принимает клики, не получает клавиатуру и не перемещает пользовательскую мышь. Ввод идёт через интерфейсы приложения, а не через виртуальную мышь/клавиатуру. Основные окна остаются на основном рабочем столе; отдельный рабочий стол не создаётся.

Приложение должно предоставлять элементы доступности. Нестандартные Canvas/игры/непредоставленные элементы не поддерживают произвольные клики по пикселям в этом режиме. Парольные поля не читаются и не редактируются. Для визуального анализа нужна модель с изображениями. Снимки передаются выбранной модели, временные файлы удаляются при завершении/отмене задачи.

Нужны системный Python 3 с PyGObject/Gio, AT-SPI и рабочий портал ScreenCast. На Niri используются screencopy и layer-shell; для изображения указателя нужны GdkPixbuf SVG и Pillow в системном Python. Для других рабочих столов подготовлен PipeWire/GStreamer путь; нужны pipewiresrc, videoconvert и pngenc. GNOME/KDE и несколько мониторов физически не проверены; отдельный указатель пока реализован и проверен на Niri. Android сохраняет свои инструменты приложений, независимое управление ПК на телефон не переносится. Windows этой частью не реализован.

В среде теста GTK запускался с `NO_AT_BRIDGE=0`: при `NO_AT_BRIDGE=1` его элементы не доступны. Xopilot убирает эту переменную только при запуске запрошенного Linux-приложения; глобальные настройки доступности пользователя не меняет.

Выполнено Codex на реальном Niri: получение полного кадра, независимый указатель без смены фокуса, замена русского/английского текста в тестовом GTK-поле и действие кнопки. Проверено сохранение активного окна. Реальный запуск через каталог Gio подтвердился созданием нового процесса тестового приложения. Контролируемая задача с настоящим Google API через сервис агента прошла: поле изменено, кнопка нажата, итоговый ответ получен. Модели передавалось только дерево собственного тестового окна, без изображения других приложений. Первый проход оборвался на TLS-таймауте при итоговом ответе; повтор с TaskControl прошёл. Браузерный проход через интерфейс Xopilot не проверен: инструмент отклонил локальную страницу. это не подтверждение поддержки любых Linux-приложений.
