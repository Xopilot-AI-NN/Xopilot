# Android на устройстве — 11 ноября 2026

Rust 2.0.13 проверен на POCO X5 5G, Android 17, arm64-v8a, 6 ГБ RAM. Используется отдельный debug-пакет **by.xopilot.preview / Xopilot Test**. Установленный **by.xopilot.app / 2.0.12** не заменялся, его данные не открывались и не удалялись.

Проверены холодный запуск, автоматически созданный профиль, открытие меню, настроек, аккаунта и «О программе» с версией 2.0.13. Изменённое имя и черновик пережили принудительную остановку процесса и повторный запуск: новая история и ключ Android Keystore остаются доступными после перезапуска.

## Системные панели и клавиатура

В Rust через JNI читаются реальные WindowInsets, включая системные панели и вырез экрана. WebView visualViewport задаёт высоту доступной области при показе клавиатуры; фиксированные окна используют ту же область. Высота клавиатуры не прибавляется повторно к нижнему отступу.

На устройстве без клавиатуры верхний отступ составил 38.52 CSS px, нижний — 24.07 CSS px при DPR 2.7. Заголовок расположен ниже строки состояния, ввод и его кнопки — выше панели навигации.

При открытии настоящей экранной клавиатуры видимая высота изменилась с 888.89 до 552.59 CSS px. Нижняя граница ввода с кнопками — 544.59 CSS px: блок полностью видим над клавиатурой. После закрытия клавиатуры восстановлены высота 888.89 CSS px и нижний системный отступ. Прокрутка страницы не смещает заголовок.

Снимки с устройства: [системные отступы](../previews/android-safe-area.png), [клавиатура и ввод](../previews/android-keyboard.png).

## Нативные библиотеки

Первоначальная установка показала системное предупреждение о 16 КиБ: LOAD-сегменты libmain.so были выровнены на 4 КиБ. В Android-ветке App/build.rs явно заданы max-page-size и common-page-size 16384. Все LOAD-сегменты libmain.so и официальной liblitert-lm.so теперь проходят проверку 16 КиБ; ZIP-выравнивание также проверено.

После обновления только тестового пакета Android сообщил **pageSizeCompat=0**, при повторном холодном запуске предупреждение не появилось. Опция «Больше не показывать» для сокрытия ошибки не использовалась. На этом телефоне ядро использует страницы 4096 байт; запуск на ядре 16 КиБ отдельно не испытывался.

```bash
./scripts/test.sh apk
# Можно проверить и отдельный APK:
./scripts/test.sh apk-check /путь/к/app-debug.apk
```

## Выбор файла и уведомления

Настоящий системный chooser Android открылся из кнопки импорта. В Downloads выбран собственный тестовый .litertlm размером 29 байт. Rust получил файл блоками и отклонил его по SHA-256, сохранив исходную причину: «Файл не совпадает с поддерживаемыми Gemma». Не устанавливалась фиктивная модель.

Проверена ошибка раннего запуска JS до создания input: обработчик теперь ожидает появление элемента. Две последовательные попытки через системный chooser показали исходную ошибку Rust без общей «Передача отменена»; после обеих попыток кнопка оставалась доступной. Уведомление об ошибке импорта автоматически исчезло примерно через 3 секунды, кнопка выбора файла снова доступна. Полный оригинальный файл модели на телефоне не импортировался.

`./scripts/test.sh bridges` воспроизводит поздний DOM и два последовательных импорта после ошибки без телефона.

## Фоновый режим и системная загрузка

Home и повторное открытие из launcher сохранили PID, JS timeOrigin и открытые настройки. Возврат занимал 32–152 мс. Раньше Back завершал Activity; теперь он закрывает окно, а из корневого чата вызывает moveTaskToBack. Проверено, что PID и состояние остаются прежними. Manifest singleTask исключает вторую Activity с повторной инициализацией ndk_context.

Отдельно установлен оптимизированный Rust/Gradle release preview без incremental ADB. С прежними данными первый кадр Activity появился за 978 мс, Fully drawn — за 1519 мс. SQLCipher открывался параллельно WebView за 303 мс; ожидание подготовленной истории со стороны UI заняло 15 мс, web_ready_ms — 529.5 от начала документа. Для сравнения, до параллельной подготовки Fully drawn составлял 1917 мс. Повторное открытие через Home заняло 67 мс и сохранило процесс. Это один замер на конкретном устройстве, а не гарантия скорости на любом Android.

В тестовом пакете запущена настоящая загрузка E4B через Android DownloadManager. Системное уведомление показывало процент; после Home процесс интерфейса уничтожен командой am kill. При следующем запуске восстановилось окно «Модель чата» и та же системная задача: 695.6 МиБ / 3.41 ГиБ, 20%. После проверки отменена только эта загрузка; ранее установленная E2B не удалялась. Полное завершение скачивания и установка E4B в этом прогоне не проверялись.

Снимок навигации, прокрутки и черновика хранится в SQLCipher. Два автоматических теста проверяют открытие той же базы новым Store и устойчивость к повреждённой UI-записи. Пароли форм и разрешения на незавершённые действия агента автоматически не восстанавливаются.

## Подпись и выпуск

Production APK использует Xopilot, by.xopilot.app, versionName 2.0.13 и versionCode 2000013. Новый постоянный сертификат записан публичным отпечатком в App/android/signing-certificate.sha256; закрытый ключ и пароли находятся вне Git. Проверены подпись apksigner и 16 КиБ ELF/ZIP-выравнивание. Прежний APK с другим сертификатом не заменялся. Для следующих Rust-версий CI восстанавливает один и тот же ключ из GitHub Secrets.

## Границы проверки

Эта проверка не подтверждает обновление старой установки с исходной подписью, работу облачного аккаунта, Google, Live, GPU или настоящего инференса на телефоне. Preview отличается applicationId и сертификатом, но собирается из того же Rust-кода. Возврат из фона и холодный запуск измерены отдельно; результаты приведены выше.

Отдельный пакет `by.xopilot.uitest` прошёл 25 проверок через ADB и WebView DevTools на POCO X5 5G. Проверены настройки, размеры окон, изменение имени, диагностика, Canvas, экспорт DOCX/XLSX, сохранение черновика, Home, Back, уничтожение процесса и настоящая экранная клавиатура.
