# Идентификатор Android-приложения

Основной пакет Xopilot: **`by.xopilot.app`**, организация — `by.xopilot`.
Значение задано в `[tool.flet.android].bundle_id` файла `pyproject.toml`.
`scripts/build_android.py` передаёт его Flet явно и проверяет фактическое имя пакета в готовой APK. Сборка GitHub Actions использует тот же скрипт и настройку.

Изменение идентификатора Android создаёт отдельное приложение с отдельными каталогами данных и Keystore. APK `by.xopilot.app` не обновляет старую `ru.xopilot.xopilot`; обе могут находиться на телефоне одновременно. Старая установка и её данные не удаляются автоматически.

Для перехода между этими установками войдите в тот же аккаунт Xopilot и разблокируйте синхронизацию своим паролем. Восстановятся только данные, действительно отправленные в облако и включённые в синхронизацию. Несинхронизированные материалы, локальные модели и временные чаты не появляются в новой установке автоматически. Защищённые чаты должны быть отдельно включены в синхронизацию; доступ к ним по-прежнему требует их пароля.

Сначала проверьте нужные данные в новой установке. До этого сохраняйте старую. Копирование каталога старого приложения через ADB не переносит его аппаратный ключ Android Keystore; автоматический локальный перенос этим изменением не реализован.

Для специального обновления старой установки при диагностике предусмотрен явный параметр:

```sh
python scripts/build_android.py --bundle-id ru.xopilot.xopilot ...
```

Этот параметр используют только намеренно. Обычная сборка без переопределения всегда создаёт `by.xopilot.app`.
