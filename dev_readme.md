# Карта проекта для разработчика

Сохраняем прежнюю архитектуру и стиль: отдельные небольшие модули, русские комментарии, имена сервисных функций и `build_*` для интерфейса. Исходники имеют расширение `.rs`; `mod.rs` объявляет содержимое папки. Точка входа находится прямо в `App/main.rs`, без переноса дерева в `src/`.

- `App/main.rs` настраивает окно и запускает Dioxus.
- `App/app/main.rs` собирает окно из меню, чата и самостоятельных страниц.
- `App/app/state.rs` содержит состояние окна и асинхронные обработчики действий.
- Компоненты используют `Signal<AppState>` из контекста. Сервисам не нужен Dioxus.
- `App/services` содержит прикладную логику. `Store::run` выполняет SQL в worker; чтение файлов, изображения и документы обрабатывает `runtime::blocking`.
- `App/settings` собирает страницы настроек; `App/app/settings` оставлен для настройки модели из интерфейса чата.
- `Services` — обычная Rust-библиотека SQLCipher. интерфейс обращается к ней напрямую.
- `App/app/theme/design.css` содержит общую тему, палитры и мобильную компоновку. Локальный шрифт упакован через `asset!`, без CDN.

Пример заголовка:

```rust
// Файл: App/services/example.rs
// Разработчик: DenBroLiik
// Описание: Конкретная ответственность модуля.
```

Не создавайте пустые Rust-модули вместо ещё не перенесённых функций. Статус переноса указан в [MIGRATION.md](MIGRATION.md). Прежний код сохранён в истории Git.

Для форм с явной кнопкой сохранения используйте `shared::unsaved::use_unsaved`; возврат по разделам настроек — через `state::select_settings_section`. Булев атрибут HTML `inert` удаляйте при открытии панели: значение `"false"` тоже блокирует взаимодействие. Проверка реальных кликов находится в `scripts/check-ui.cjs` и `App/examples/interface_interaction.rs`; обычный SSR не обнаруживает заблокированные элементы.

Не редактируйте выпущенные SQL-миграции. Сохраняйте неизвестные поля JSON и прежние ключи настроек. Тесты используют временные каталоги и SQLCipher с отдельным тестовым ключом; пользовательская база в проверках не открывается.

Команды сборки и проверки перечислены в [README.md](README.md).

- `services/litert.rs` ограничивает небезопасный C ABI RAII-объектами и одним сериализованным engine; callback освобождается только после `wait_until_done`.
- `services/model_installer.rs` публикует веса после SHA-256; пауза оставляет `.part`, а файловая блокировка исключает конкурирующую запись.
- `services/agent.rs` вызывает только объявленные инструменты, ждёт подтверждения записи/команд и проверяет результаты. Остановка завершает группу процессов, а повторные одинаковые результаты переводят агента к подведению итога без инструментов.
- `shared/popover` ставит меню по кнопке с учётом `visualViewport`, изменения размеров и прокрутки; скрытые desktop-кнопки заменяются мобильными якорями.

- `settings/account` содержит профиль, аватар, серверную авторизацию и автоматически созданный профиль; `settings/models`, `settings/updates`, `app/models`, `app/materials`, `app/tasks` содержат рабочие компоненты по прежним границам папок. Пустые каталоги от кеша удалены.
- `litert` хранит conversation/KV-кеш, пока история является точным продолжением. Изменение инструкций или прошлого сообщения пересоздаёт conversation; смена чата вызывает `reset_context`, смена аккаунта выгружает engine.
- Короткие CSS/JS-ресурсы нужны WebView: они позиционируют меню, управляют фокусом и передают выбранный Android-документ блоками. Прикладная логика находится в Rust.

- RSX записываем развёрнуто: каждый элемент и атрибут на отдельной строке, обработчики с явными блоками. Не уплотняем разметку в одну строку. Возле функций оставляем короткое описание ответственности и ограничений.
- `agent_protocol` разбирает полный JSON даже после пояснения, не пропускает обрывок команды в обычный ответ. `agent_session` сопоставляет чистую историю SQLCipher с расширенным разговором инструментов; это позволяет продолжать тот же KV-контекст.
- `compute` выбирает backend по свободной памяти с запасом. `generation` не показывает загрузку, если engine уже существует, и не повторяет запрос после первого выданного токена.
- `shared/progress` использует дробь только при известном размере. При открытом диалоге `activity_dock` отображается внутри него; над вводом второго экземпляра нет.
