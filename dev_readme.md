# dev_readme.md — карта проекта для разработчика

Файл: /dev_readme.md
Разработчик: DenBroLiik
Описание: что за что отвечает в репозитории, что класть в какую папку и какой
шапкой открывать новый файл. Не путать с README.md (публичное описание для
пользователей) и DEV.md (текущий статус фич/сборки/тестов, дневник изменений).
Обновлять этот файл при изменении структуры каталогов, а не при каждой фиче.

## Карта каталогов

### Клиент — `App/` (Python, Flet)
- `App.py` — точка входа, поднимает Flet-приложение (`flet run App/App.py`).
- `app/` — экраны и виджеты интерфейса: `main.py` (сборка UI), `menu.py`,
  `chats.py`/`chat.py`, `message.py`, `material.py` (тема Material You),
  `backgraund.py`, `prompt.py`, `workspace_browser.py`, `progress.py`,
  `buttons/` — переиспользуемые кнопки. Сюда — только UI-код, без прямых
  вызовов БД/сети (это через `services/`).
- `services/` — Python-слой бизнес-логики: `db.py` (обёртка над Rust-модулем
  `advanced_xopilot`), `ai.py`, `llm.py` (LiteRT-LM, локальная модель),
  `chat_store.py`, `stats.py`. Любой вызов нативного модуля — в try/except,
  чтобы UI открывался, даже если `advanced_xopilot` ещё не собран.
- `core/` — **устаревшая папка**, переименована в `services/`. Новые файлы
  сюда не класть, оставшийся мусор дочистить и удалить каталог.
- `settings/` — экраны настроек. Конвенция подпапки на один раздел настроек:
  `main.py` (сборка экрана) + файлы-фичи (`theme.py`, `language.py`,
  `check_button.py`, `list.py`, `clear_button.py`...) + `buttons/` под
  локальные кнопки раздела. Есть `abaut/` (опечатка вместо `about/` — при
  переименовании поправить импорты в `settings/main.py`).
- `assets/` — то, что реально паковится в приложение: `Icons/`, `fonts/`,
  `models/` (`sentiment.onnx`). Это копия из корневых `Icons/`/`fonts/` —
  при обновлении иконок/шрифтов обновлять оба места (или завести скрипт
  синхронизации в `scripts/`).
- `data/models/` — тяжёлые веса модели (`*.litertlm`, `*.xnnpack_cache`).
  В git не коммитятся (см. `.gitignore`), только `.gitkeep`.
- `native/` — **генерируется** сборкой `Services/` (`maturin develop`/
  `scripts/build_native.py`) в cdylib `advanced_xopilot`. Руками не редактировать
  и не коммитить бинарники.
- `requirements.txt` — зависимости конкретно клиента (отдельно от корневого
  `pyproject.toml`, который описывает пакет `Xopilot` и Flet-сборку).

### `Services/` — Rust cdylib `advanced_xopilot` (PyO3 → `App/native/`)
`src/lib.rs` — точка сборки модуля, регистрирует классы для Python.
Подпапки — один модуль = одна зона ответственности:
`db/` (SQLCipher CRUD), `security/` (ключ шифрования из OS keyring),
`ai/` (тестовый ONNX-классификатор тональности), `cloud_sync/`, `mcp/`,
`updates/` (заглушки под фазу 2), `chat_gpt_api/`. Рабочий ИИ **не здесь** —
переехал в `App/services/llm.py` (LiteRT-LM), Rust это не трогает.

### `Server/` — отдельный Rust-бинарник (Axum + SQLite, sync-сервер)
На диске сейчас только `Cargo.lock`/`target` — `Cargo.toml` и `src/`
отсутствуют (перед новой сессией разработки восстановить/пересоздать).
Когда есть исходники — свой `Server/README.md` с установкой/systemd/HTTPS,
сюда в общую карту детали сервера не дублировать.

### `libs/` — общие библиотеки вне Services/App
`api_zgft/main.py` — заглушка (0 байт), под будущий Python API-обвязку.
Тут же по роадмапу должны появиться Mojo-библиoteки (AI); на Mojo-файлы
конвенция шапки пока не устаканена — см. секцию ниже, предлагается тот же
формат, что и у Rust (`#` вместо `//`).

### Обвязка сборки/запуска
- `python/android/`, `python/linux/` — portable-интерпретаторы Python на
  каждую платформу (venv). Запуск через них (`./python/linux/bin/flet run
  App/App.py`), в системный Python ничего не ставить. Руками не редактировать.
- `scripts/` — вспомогательные скрипты сборки, напр. `build_native.py`
  (собирает `Services/` через maturin, кладёт .so/.pyd в `App/native/`).
- `tests/` — Python `unittest` (БД/крипто/UI/медиа) + `sync_e2e.py`
  (интеграционный тест синхронизации на loopback-сервере, без пользовательских
  чатов). Запуск: `python -m unittest discover -s tests -v`.
- `build/` — **полностью генерируемый** вывод `flet build` (Flutter-обвязка,
  site-packages и т.д.). В git не идёт, можно удалять целиком в любой момент.
- `.github/workflows/build.yml` — CI: по тегу `v*`/`dev-*` собирает Linux/
  Windows через `flet build`, паковит zip, публикует GitHub Release. Rust-части
  (`Services/`, `Server/`) в CI сейчас не собираются — только Flet-клиент.

### Корень
- `Icons/`, `fonts/` — исходные/мастер-файлы дизайна (сюда добавлять новые
  иконки/шрифты), из них копируются рабочие версии в `App/assets/`.
- `generate_sentiment_model.py` — разовый скрипт, генерирует
  `App/assets/models/sentiment.onnx`.
- `pyproject.toml` — метаданные пакета `Xopilot` + конфиг `flet build`
  (`[tool.flet]`).
- `LICENSE` — MIT, правообладатель DenBroLiik (Xopilot).
- `README.md` — публичная страница проекта (описание, история версий,
  скриншоты). Структуру репозитория сюда не писать — для этого есть этот файл.
- `DEV.md` — текущий статус: что реализовано, схема БД/синка, команды сборки
  и тестов, известные ограничения. Обновлять по факту крупных изменений.
- `dev_readme.md` — этот файл.

## Шапка файла при создании

Конвенция уже используется в проекте — новый файл открывать так же.

**Python** (`.py`):
```python
"""
Файл: <путь от корня репозитория>
Разработчик: DenBroLiik
Версия: X.X.X   # опционально — если у конкретного файла своя версия
Описание: <что делает файл, ключевые нюансы/зависимости>
"""
```

**Rust** (`.rs`):
```rust
// Файл: <путь от корня репозитория>
// Проект: Xopilot AI+ NN+
// Разработчик: DenBroLiik
// Версия: X.X.X
// Описание: <что делает файл>
```

Для точки входа приложения (`App/App.py`) шапка расширяется приветственным
баннером сверху (см. сам файл) — это исключение, не тиражировать на рядовые
модули.

## Прочие соглашения по коду

- Любой импорт нативного Rust-модуля (`advanced_xopilot`) — в try/except с
  сохранением `_IMPORT_ERROR`, чтобы UI поднимался и без собранного модуля.
- Шифрование БД всегда включено, ключ только из OS keyring — не добавлять
  диалоги ввода пароля/PIN, пока нет сервера/passkeys (см. DEV.md).
- В `.gitignore` — не коммитить: `*.lock`, `target`, `build`, `*.db`/`*.sqlite*`,
  веса моделей (`*.gguf`, `*.litertlm`, `*.xnnpack_cache`), `.xopilot_salt`,
  `DEV.md` (не путать — он в .gitignore, живёт только локально/не в репо).
