# Xopilot Flow Map

Локальная карта выполнения Rust. События показываются узлами, причинные связи — стрелками. Инструмент читает JSONL и JSON, записанные отмеченными операциями приложения.

## Запуск

Из корня проекта выполните одну команду.

```bash
./scripts/fmap
```

Команда запускает Xopilot с трассировкой, локальный сервер и системный браузер. Новый журнал подключается автоматически и обновляется раз в секунду. Во время сборки просмотрщик ожидает первые события. После закрытия приложения карта остаётся доступной. `Ctrl+C` завершает приложение и сервер вместе. Для запуска нужны Rust/Cargo, Dioxus CLI (`dx`) и Node.js, для интерфейса Xopilot — его обычные системные зависимости.

```bash
./scripts/fmap --demo          # Демонстрация потоков, async-задач и файловых операций
./scripts/fmap --no-browser    # Адрес печатается в терминале
./scripts/fmap --values        # Записывать также значения переменных
./scripts/fmap --help
```

Для каждого запуска создаётся отдельный файл `target/flow-traces/xopilot-<время>-<PID>.jsonl`. По умолчанию сервер выбирает свободный порт на `127.0.0.1`. Фиксированный порт можно задать через `FLOWMAP_PORT=8787 ./scripts/fmap`.

Ранее записанный журнал можно открыть отдельно.

```bash
node tools/flowmap/serve.cjs target/flow-traces/xopilot-1234.jsonl
```

Сервер напечатает адрес. Кнопка «Обновлять файл» подключает журнал, а добавление `/?live=1` к адресу включает чтение автоматически. Запуск `node tools/flowmap/serve.cjs` открывает просмотрщик на порту 8787 с ручным выбором файла.

Просмотрщик также открывается прямо из `tools/flowmap/nodes.html`. Адреса `index.html` и `viewer.html` ведут к актуальному интерфейсу, старый линейный просмотрщик сохранён как `viewer-legacy.html`.

## Что показывает интерфейс

- Все события доступны через страницы по 500 узлов, поиск и фильтры потоков и типов. Импорт ограничен 100 000 событий и 64 МиБ.
- Основная раскладка — дерево слева направо. Дочерние операции располагаются справа от родителя, независимые ветки разделены по вертикали. Для событий без `parent_id` используется порядок внутри потока. Кнопка «По потокам» переключает на дорожки потоков, «Дерево» возвращает основную раскладку.
- Сплошные связи используют явный `parent_id`. Пунктир показывает соседние записи одного потока в одной сессии.
- Инспектор показывает описание, значения, исходный файл и строку, сессию, длительность и соседние связи.
- «Предыдущее событие», «Следующее событие» и стрелки клавиатуры перемещают выделение. «Просмотр» воспроизводит последовательность с паузой.
- Ноды можно перемещать. Поиск, страницы и смена раскладки сохраняют их координаты. Раскладка экспортируется в JSON и восстанавливается через «Открыть раскладку».
- «SVG» сохраняет видимую страницу графа. «JSONL» сохраняет всю импортированную трассу, включая поля исходного журнала.
- «Обновлять файл» повторно читает выбранный файл раз в секунду. При подключении журнала через CLI используется локальный сервер. При отдельном выборе обновляемого файла нужен браузер с File System Access, например Chrome или Edge, и разрешение на выбранный файл. Незавершённая последняя строка ожидает следующего обновления. Ошибка в завершённой строке отображается в интерфейсе.
- Колесо масштабирует карту относительно курсора, перетаскивание фона перемещает её. Мини-карта переносит видимую область, `F` вписывает граф, `/` открывает поиск.

## Подключение событий

`App/flow_trace.rs` — основная реализация. Она уже подключена через `App/lib.rs`. Стартовые события есть в `App/main.rs`, а общий фоновой runtime отмечает задачи и блокирующие операции. Для подробной карты добавляйте события в интересующие функции.

```rust
use xopilot::flow_trace as trace;

let operation = trace::span("Чтение настроек");
let text = trace::read_to_string(path.as_ref())?;
trace::variable("bytes", &text.len());
trace::decision("Настройки присутствуют", !text.is_empty());
drop(operation);
```

`read_to_string` и `write` выполняют файловую операцию и связывают с ней результат или ошибку. Для обычных отметок доступны `begin`, `step`, `call`, `decision`, `variable`, `error`, `end`.

Синхронный `span` принадлежит одному потоку и завершается при Drop. В асинхронном коде используйте `scope`, которая устанавливает родительский контекст на время каждого poll.

```rust
trace::scope("Загрузка", async {
    trace::step("Перед ожиданием");
    tokio::task::yield_now().await;
    trace::step("После ожидания");
}).await;
```

Для нового потока или независимой async-задачи передавайте родителя явно через `span_with_parent` или `scope_with_parent`. Токен доступен из `span.id()` и `current_id()`. Синхронный guard следует завершить до `await`. Пример параллельной работы и отмены находится в `App/examples/flowmap_nodes_demo.rs`.

## Журналы

Каждый запуск получает UUID сессии. Номер `seq`, время и строка JSON назначаются под одной блокировкой. Повторные запуски могут дописывать один файл, их ID остаются уникальными. Одновременно журнал принадлежит одному процессу. Блокировка хранится в соседнем `.lock`, поэтому чтение данных остаётся доступным. Если прежний процесс оставил незавершённую строку, для следующего запуска следует выбрать новый путь журнала.

- `XOPILOT_FLOW_TRACE=1` включает запись.
- `XOPILOT_FLOW_PATH` выбирает путь.
- `XOPILOT_FLOW_VALUES=1` включает значения переменных. По умолчанию вместо них записывается отметка скрытия.
- `XOPILOT_FLOW_MAX_EVENTS` задаёт число событий, по умолчанию 100 000. Также действует ограничение файла 64 МиБ. При достижении лимита запись останавливается.

Значения, сообщения ошибок и пути попадают в локальный журнал. Выбирайте отмечаемые данные с учётом содержимого. На Unix новые файлы создаются с правами `0600`. Каталог `target` исключён из Git. Просмотрщик сохраняет чтение прежних форматов v1/v2.

## Проверка

```bash
./scripts/test.sh flowmap
./scripts/check.sh
```

Первый сценарий проверяет горизонтальное дерево, циклы и длинные цепочки, единый запуск с очисткой процессов, импорт, многостраничные трассы, старые форматы, реальные параллельные записи, async/await, отмену Future, файловую ошибку, лимит и скрытие значений. Артефакты находятся в `target/flowmap-check-*`.

Карта показывает фактически отмеченные пути выполнения. Статический граф всего исходного кода и автоматическая остановка программы на узле требуют отдельной интеграции с компилятором или отладчиком. CodeLLDB можно использовать параллельно, передав `XOPILOT_FLOW_TRACE=1` в его окружение.
